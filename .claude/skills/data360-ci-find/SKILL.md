# Data360 CI Find — Concept → DMOs, Fields, Example CIs

Answer "I need to build/edit a CI about X — where do I start?" for the current client. Reads the client's `concept-map.yaml` (hand-curated), `object-model/dmo-usage.yaml` (generated by `ci_concordance.py build`), and per-DMO sidecars from `object-model/dmos/*.yaml` (generated by `intake.py`).

Zero LLM inference at lookup time. Pure YAML resolution.

## Prerequisites

- **Intake has been run** (`object-model/dmos/*.yaml` and `queries/*.sql` exist).
- **`ci_concordance.py build` has been run** for the current client — writes `object-model/dmo-usage.yaml` and `object-model/dmo-usage.md`.
- **`concept-map.yaml` exists** at the client's Data360 root — hand-curated. If missing, only the DMO / field substring matches work; the concept lookup returns "no concept-map entry".

To seed `concept-map.yaml` for a new client, run `ci_concordance.py propose --all --output-dir <client-data360>` — prints candidate YAML blocks for review.

## Invocation

`/data360-ci-find <term>` — the term is a business concept (e.g. "CLV", "Market Coverage") or a DMO/field name.

`/data360-ci-find propose <term>` or `--all` — emits a candidate `concept-map.yaml` block for review (never edits the file directly).

The skill resolves paths from the current working directory when it's under a client's `Data360/` folder; otherwise the user passes `--output-dir <client-data360>` on the underlying command.

## Lookup resolution order

Case-insensitive matches; first hit wins.

1. **Concept-map key or alias** — exact match on a top-level key or an entry in its `aliases` list. Returns the concept's DMOs, `key_fields`, glossary blurb (if available), and 3–5 example CIs from `dmo-usage.yaml`.
2. **DMO name substring** — matches against any DMO key in `dmo-usage.yaml`. Returns that DMO's row (fan-in, top fields, top join partners, example CIs).
3. **Field name substring** — matches against any field name across `dmo-usage.yaml` `top_fields` lists. Returns the DMOs carrying that field, ranked by fan-in.
4. **Glossary heading** — falls back to `glossary.md` if present. Returns the definition prose plus a prompt: "no concept-map entry yet — run `/data360-ci-find propose <term>` to draft one".

## Output shape

```
## CLV — Customer Lifetime Value
Glossary: total projected revenue from a customer over the relationship.

DMOs (by CI fan-in):
- ssot__Account__dlm — 17 CIs
  key fields: ssot__AccountTypeId__c (Account Type), ssot__AnnualRevenue__c (Annual Revenue),
              ssot__IndustryId__c (Industry)
- ssot__SalesOrder__dlm — 8 CIs
  key fields: ssot__CustomerAccountId__c, ssot__TotalAmount__c

Example CIs to crib from:
- CLV_By_Account__cio
- CLV_Rolling_12M__cio
- CLV_Segment_Ready__cio
```

Field descriptions come from `<client-data360>/object-model/dmos/<dmo>.yaml` (`fields[].label`). If a DMO sidecar is missing (e.g. intake hasn't been refreshed), the field's description is elided — the field name alone still surfaces.

## Propose flow

`/data360-ci-find propose <term>` runs the discovery pipeline:

1. Match CIs by filename token (case-insensitive, word boundary) against the term and any glossary-listed aliases.
2. Rank DMOs referenced by ≥25% of matched CIs.
3. Rank fields projected by ≥50% of matched CIs — these become `key_fields`.
4. Emit a `concept-map.yaml`-shaped block to stdout with matched-CI count and rationale as leading comments.

Known failure mode: concepts with no filename signal (the DMO-first case — e.g. an org where every CI touching `Sales_Forecast_Period__dlm` uses a different filename prefix) return no proposal without hand-authored aliases. First-time seeding is manual; subsequent proposals feed on those aliases.

`--all` walks every `## Heading` in `glossary.md` (or filename token clusters if no glossary exists) and prints a block per term with ≥3 matched CIs. One-time bootstrap; expect to hand-edit before pasting into `concept-map.yaml`.

## Regeneration

`dmo-usage.yaml` should regenerate as part of the client's refresh flow:

```bash
data360 ci-concordance build \
    --output-dir ~/Projects/clients/<client>/Data360
```

`concept-map.yaml` is git-tracked per client and hand-edited only. Never overwritten by the toolkit.
